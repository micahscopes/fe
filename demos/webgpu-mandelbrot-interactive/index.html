Interactive Fe mandelbrot

The Fe compiler compiled both the fractal and the pan/zoom controls. The picture is a Fe @fragment shader (Fe -> SPIR-V-IR -> WGSL) your GPU draws every pixel of; the controls are the Fe fn update_view (Fe -> wasm) your browser runs. JavaScript only forwards pointer/wheel events - it does no view math, no pixels, no palette.

Provenance: these files were produced by cargo run -p fe-codegen --example gen_mandelbrot_interactive_demo, which compiles the SSOT fragment through the Render seam and the SSOT controls to wasm, and hard-fails unless the WGSL validates on the browser profile, the wasm export signatures match, and every 512x512 pixel equals the in-generator oracle at the pinned views.
GREEN "your GPU drew every pixel" is earned only when the Fe render pipeline draws the canvas on a live WebGPU device, the readback byte-equals the Fe-wasm fragment per pixel, and the default-view FNV equals the compiled reference. No WebGPU shows AMBER (the Fe fragment still computes every pixel in V8, the Fe controls still run in V8; the GPU claim is withheld). A shader error or a per-pixel GPU/Fe mismatch shows RED. The browser consumes naga-emitted WGSL; the SPIR-V words are the lavapipe-verified twin from the same validated module.
