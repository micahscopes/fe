Interactive Fe Desargues' theorem

Every line and point on the canvas is a projective incidence computed by Fe's CTFE-planned meet & join — ganja.js's ^ and & for the plane Cl(2,0,1), folded to a survivor mask at compile time and machine-derived into a @fragment shader (Fe → SPIR-V-IR → WGSL). Two triangles are perspective from the point O; the three intersections of their corresponding sides are collinear — they sit on the gold axis of perspectivity for every sweep, which is Desargues' theorem, live. The controls are the Fe fn update_desargues (Fe → wasm) your browser runs. JavaScript only forwards pointer/wheel events — it does no geometry, no pixels, no color.

Provenance: the render fragment (frag.wasm / frag.wgsl / manifest.json) is produced by the shipped fe web build CLI against demos/sketches/desargues; the meet/join kernel it derives is dual-gated bit-for-bit against a hand-tabled cross product in crates/codegen/tests/pga2d_meet_join_plan.rs, which also checks the three cross-points are collinear. The drag controls (ctl.wasm / ctl.json) are produced by cargo run -p fe-codegen --example gen_desargues_interactive_ctl, which hard-fails unless the wasm export signature is exactly (f32,f32,f32,i32,i32,i32) -> (f32,f32,f32) and wasmtime's execution matches an independent Rust oracle bit-for-bit across directed cases plus a 2,000-step random walk. Both halves are regenerated by ./generate.sh (gitignored gen/, never hand-edited).
WEBGPU "your GPU drew every pixel" is earned only when a live WebGPU adapter renders the canvas. No WebGPU shows AMBER (the Fe fragment still computes every pixel in V8, the Fe controls still run in V8; the GPU claim is withheld). A shader error or a controls/oracle mismatch shows RED.
