Interactive Fe cga3d Pencil

The Fe compiler compiled both the pencil-of-spheres fragment and the drag controls. The picture is a Fe @fragment shader (a REAL sparse Cl(4,1) incidence contraction, five planned products, not a hand-derived formula), Fe -> SPIR-V-IR -> WGSL, drawing the y = 0 slice of a pencil of spheres; the controls are the Fe fn update_pencil (Fe -> wasm) your browser runs - drag composes the next (lambda, theta, zoom), the SAME three uniforms the fragment reads. JavaScript only forwards pointer/wheel events - it does no pencil math, no pixels, no color.

Provenance: the render fragment (frag.wasm / frag.wgsl / manifest.json) is produced by the shipped fe web build CLI against demos/sketches/cga3d; the drag controls (ctl.wasm / ctl.json) are produced by cargo run -p fe-codegen --example gen_cga3d_interactive_ctl, which hard-fails unless the wasm export signature is exactly (f32,f32,f32,i32,i32,i32) -> (f32,f32,f32) and wasmtime's execution matches an independent Rust oracle bit-for-bit across directed cases plus a 2,000-step random walk. Both halves are regenerated by ./generate.sh (gitignored gen/, never hand-edited).
WEBGPU "your GPU drew every pixel" is earned only when a live WebGPU adapter renders the canvas. No WebGPU shows AMBER (the Fe fragment still computes every pixel in V8, the Fe controls still run in V8; the GPU claim is withheld). A shader error or a controls/oracle mismatch shows RED.
